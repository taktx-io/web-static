Already using Camunda 8?

Your BPMN models run almost natively. Your workers need just two small changes.

TaktX reads the same BPMN 2.0 XML produced by Camunda Desktop Modeler. Worker migration is limited to swapping import packages and replacing ActivatedJob with ExternalTaskTriggerDTO.

Camunda 8 / Zeebe Before 
import io.camunda.zeebe.spring.client.annotation.CustomHeaders;
import io.camunda.zeebe.spring.client.annotation.JobWorker;
import io.camunda.zeebe.spring.client.annotation.Variable;
import io.camunda.zeebe.client.api.response.ActivatedJob;

public class ExampleWorker {

    @JobWorker(type = "process.actions.promote-variables")
    public Map<String, Object> handle(
            ActivatedJob activatedJob,
            @Variable List<String> variableNameList,
            @Variable String instanceId,
            @CustomHeaders Map<String, String> headers) {

        return Map.of("var1", "value1", "var2", "value2");
    }
}
TaktX After 
import io.taktx.client.annotation.CustomHeaders;
import io.taktx.client.annotation.JobWorker;
import io.taktx.client.annotation.Variable;
import io.taktx.dto.ExternalTaskTriggerDTO;

public class ExampleWorker {

    @JobWorker(type = "process.actions.promote-variables")
    public Map<String, Object> handle(
            ExternalTaskTriggerDTO triggerDTO,
            @Variable List<String> variableNameList,
            @Variable String instanceId,
            @CustomHeaders Map<String, String> headers) {

        return Map.of("var1", "value1", "var2", "value2");
    }
}
Import packages
io.camunda.zeebe.*
→ io.taktx.*
Trigger type
ActivatedJob
→ ExternalTaskTriggerDTO
Everything else
Same annotation, same @Variable & @CustomHeaders, same return type — no other changes needed

Why (not) TaktX?

We believe in honest positioning. TaktX is a strong fit for some teams — and not the right choice for others.

thumb_up

TaktX is a good fit when...

  • check_circle You need high-throughput, event-driven orchestration
  • check_circle Security, trust, and message integrity are requirements
  • check_circle You want operational control at a business level
  • check_circle Full deployment flexibility matters (on-prem, cloud, hybrid)
  • check_circle You want production-grade orchestration without enterprise licensing overhead
thumb_down

TaktX may not be the right fit if...

  • cancel You need a fully managed SaaS platform today — TaktX SaaS is still in development
  • cancel You prefer code-first workflow models (like Temporal) over BPMN
  • cancel You need a fully integrated enterprise suite (modeling, task management, analytics) available out of the box today
