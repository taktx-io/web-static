Why separate decisions from processes

Externalizing decision logic from BPMN improves model clarity, reuse, and maintainability. A BPMN process describes the flow; a DMN decision table describes the logic — keeping each concern in the right place.

Some platforms introduce additional infrastructure to execute decisions separately, increasing latency and operational overhead. TaktX evaluates decisions directly within the execution flow, keeping architectures simpler and more predictable.

Execution model

TaktX evaluates BPMN and DMN within the same event-driven runtime. This avoids cross-service communication, reduces latency, and simplifies deployment.

No need for dedicated decision services, separate scaling strategies, or additional infrastructure components.

Example

A BPMN process calling a DMN decision table to evaluate loan risk, with a FEEL expression used in a decision table cell.

Process flow BPMN + DMN 
Process: Loan Application
  → Evaluate Risk   (DMN decision table)
        ↳ input:  applicantScore, requestedAmount
        ↳ output: riskScore
  → Gateway: riskScore
        ↳ riskScore ≤ 0.4  → auto-approve
        ↳ riskScore ≤ 0.7  → manual review
        ↳ riskScore > 0.7  → reject
FEEL expression — decision table cell FEEL 
if riskScore > 0.7 then "manual" else "auto"
