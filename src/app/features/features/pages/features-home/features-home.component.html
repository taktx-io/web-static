Works with any Kafka-compatible broker

TaktX is built on the Kafka protocol — not tied to a specific vendor. Use Apache Kafka, Confluent Platform, Redpanda, AWS MSK, Axual, or any other Kafka-protocol compatible broker. Bring your own infrastructure, keep your existing investment.

Migrating from Camunda 8

TaktX reads the same BPMN 2.0 XML produced by Camunda Desktop Modeler. Worker migration requires just two changes.

Swap the import package names from io.camunda.zeebe.* to io.taktx.*, and replace ActivatedJob with ExternalTaskTriggerDTO. The annotation, parameter annotations and return type remain unchanged.

Camunda 8 / Zeebe Before
TaktX After
1. Import packages
io.camunda.zeebe.*
→ io.taktx.*
2. Trigger type
ActivatedJob
→ ExternalTaskTriggerDTO
3. Everything else
Annotation, @Variable, @CustomHeaders and return type stay exactly the same

Developer experience

Workers are plain Java classes. Annotate a method with @JobWorker, declare your variables with @Variable, and return a map — TaktX handles the rest. This example shows a multi-instance process: one worker builds the collection, another processes each item in parallel.
